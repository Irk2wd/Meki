# PicGo 图床

0.12.0 已提供 PicGo 桌面版的本机 Server 接口，Windows 与 macOS 共用实现。0.12.1 增加单图操作和图片目录设置；开发验证使用隔离文稿和模拟 PicGo 服务，不上传到用户图床。

## 使用

1. 在 PicGo 中配置并选定图床，开启 PicGo Server。
2. 打开Meki工具栏“图床”或“文件 → 图床设置…”，填写 PicGo 的端口，默认 36677。点击“检测连接”会保存设置并发送心跳，不会上传测试图片或剪贴板内容。
3. 已有文稿使用“上传文稿图片…”，预览不同图片数量、大小及跳过的网络地址，再开始上传。原图不删除，只有全部结果有效时才改文稿引用；检查后手动保存，支持撤销。
4. 可选开启“插入图片时自动上传”。只影响随后选择、粘贴、拖入的新图片，默认关闭。上传失败或取消等待时使用本地附件流程，未命名文稿会询问保存位置；取消该保存对话框则不插入图片。

手动上传需文稿已保存，以确定授权目录。允许当前文稿目录或已打开工作区中的本地图片，以及支持格式的 base64 嵌入图片；不读取网络共享、越界路径、符号链接或受保护目录。每批最多 32 张不同图片，每张最多 20 MiB，总计 80 MiB。

图床账号、上传插件、命名和云端密钥均由 PicGo 管理。Meki不读取它们，也不自动启动 PicGo、安装插件或执行上传命令。检测成功只说明本地 Server 可用，不证明云端图床凭据有效。旧版 PicGo 若没有心跳接口，会提示升级；正常非空图片上传仍可尝试。

## 单张图片与本地目录（0.12.1）

图床设置中的“本地图片目录”以文稿目录或当前工作区为基准，可写 `images/${filename}`、`${filename}.assets` 或 `.`。只能使用授权目录内的相对路径，不支持 `..`、绝对路径和链接目录；工作区模式需要先打开包含当前文稿的文件夹。已有图片不会随设置变化自动移动。

编辑模式中右键图片或点图片旁 `⋯`，本地／嵌入图片可选择单张上传 PicGo，或复制到指定目录并填写新名称。网络图片可选择下载到本地；只有明确执行下载时才发起请求。下载限制为公开 HTTP(S) 地址、最多 20 MiB，拒绝凭据、内网地址、活动 SVG 和无法识别的图片，可取消等待。

这些操作更新当前文稿中同一地址的所有图片引用，保留尺寸与说明，不修改其他文稿。复制不删除原图，撤销只恢复引用，已完成的副本仍可供快照和恢复内容使用；同名文件不会被覆盖。操作前后复验文稿和原图，失败或取消时只回收本次且未被外部修改的副本。

## 数据与失败处理

向 PicGo 发送的是经过验证的临时副本路径。原图、文稿磁盘文件和图床配置不会被上传步骤修改；返回的 HTTP(S) 地址保留 PicGo 自带的查询参数，不再拼接旧本地路径的 query／fragment。替换时保留 Markdown 说明、title、受限 img 的 width／height，忽略代码围栏、普通链接与 YAML 中的伪图片。

手动上传前后复验磁盘文稿、工作区与原图。外部变化、无效地址、部分结果、超时或取消均不替换原引用；远端可能已经上传部分图片，需要在 PicGo／图床中查看。Meki不自动重复上传，也不尝试删除远端图片。取消只停止等待，不能撤回已经交给 PicGo 的操作。

批量替换是一个可撤销编辑，暂停文稿自动保存；崩溃恢复保留未保存的新引用。新插入自动上传仍遵循文稿的常规自动保存设置。临时副本位于用户数据目录的 `image-upload-temp/`，请求完成时只清理仍归属本次请求的文件，不递归清理被外部替换的目录。

## 协议依据

PicGo 的公开接口为 `POST http://127.0.0.1:36677/upload`，JSON `list` 为绝对路径数组；响应包含 `success` 与 `result` URL 数组。空请求或空 list 可能上传剪贴板，所以Meki始终拒绝空上传请求。见 [PicGo Server 文档](https://docs.picgo.app/gui/guide/advance#picgo-server-usage)与 [Core Server 文档](https://docs.picgo.app/core/guide/commands#server)。

[PicGo GUI v2.4.0 路由源码](https://github.com/Molunerfinn/PicGo/blob/v2.4.0/src/main/server/routerManager.ts)定义 `POST /heartbeat`，成功结果为 `alive`；[v2.2.0 路由](https://github.com/Molunerfinn/PicGo/blob/9274b3f8be595d6a16c861caf58cfa217952e9c9/src/main/server/routerManager.ts)没有该接口。因此检测失败不会改用空上传请求。

批量图片通过本项目的 Markdown token 解析覆盖全文，不依赖已进入视口的图片节点。源码和资源由本项目独立实现。当前未实现任意 CLI 上传脚本、网络图片直接重新上传或 YAML 触发上传；功能边界以本仓库实现和测试为准。
