# 应用架构

Meki 使用 Electron、Milkdown/ProseMirror、CodeMirror、MathJax 和 Mermaid，Windows/macOS 共用业务逻辑。项目自有代码采用 MIT，第三方组件保留各自许可证，见根目录声明。

## 名称与兼容标识

`electron/app-identity.cjs` 将显示名与兼容身份分开。显示名来自 `package.json`，当前为 Meki；应用标识保持 `io.moye.editor`，用户配置位于系统应用数据目录下的 `Moye`，测试使用独立的 `MOYE_USER_DATA`。启动器与主进程在申请单实例锁和读取恢复数据前应用相同规则，显示名调整不会创建空配置目录或搬动用户文稿。Windows 可执行文件仍为 `Moye.exe`，保留已有 OpenWith 注册；系统显示名、快捷方式和主安装器使用 Meki，Mac 应用包使用 `Meki.app`。

签名清单、代码包及兼容安装器保留 `Moye` 文件名前缀、公钥和启动协议。主安装器使用 Meki 名称，构建工具从同一已验证安装器建立字节相同的兼容文件，再用兼容文件名签署清单。验证同时检查主文件、兼容文件及代码包，拒绝任一文件被替换。协议及发布要求见 [更新维护](updates.md)。

## 编辑器数据流

```text
Markdown 文件 → 主进程读入文本与 SHA-256 → 内存原文
                                           ├─ ProseMirror 视觉编辑
                                           └─ CodeMirror 源码编辑
保存 ← 冲突检测与原子替换 ← 同步读取当前模型 ← 用户输入
                                             └─ 本地恢复草稿
```

`src/editor.ts` 负责编辑内核；`src/main.ts` 连接窗口 UI 与当前文稿；`src/document-tabs.ts` 管理每个标签的原文、已保存基线、编辑状态、暂停原因及会话。`src/pane-workspace.ts` 为各文稿保留独立的 WritingEditor、ProseMirror 与 CodeMirror 状态；每栏显示其中一份，其余编辑器 DOM 暂存于脱离文档的容器。切换标签与拖动分栏移动已有视图，保留撤销、选区和滚动；关闭提交成功后才销毁编辑器。异步序列化回调绑定所属文稿，切换当前文稿时使旧编辑器的待处理粘贴和延迟聚焦失效，避免晚到操作写入后台文稿或抢回焦点。源码转视觉编辑时分隔撤销组，随后输入不会与整份转换合并撤销。没有编辑时保存原始 Markdown；发生视觉编辑后按编辑器模型序列化。`src/markdown.ts` 在模型外保留 YAML 前缀，导出也使用同一分离逻辑。

分栏使用最多四叶的二叉树，节点保存方向、比例，叶子保存标签顺序及各栏当前文稿。`electron/pane-layout.mjs` 同时供 renderer 与主进程使用，验证深度、数量、比例、唯一分组和完整文稿归属；旧会话可不含 layout。拖动标签支持四边预览、移入和排序，移空的分栏自动折叠；分隔线支持指针、方向键、Home 与双击，Esc 取消未完成手势。结构变化才重建分栏容器，输入不重建编辑区。布局写入沿用会话原子提交；失败恢复原布局并保留编辑内容。销毁编辑器前同时核对本次已提交会话和当前 UI，较早的写入完成不能提前销毁仍等待关闭提交的视图。恢复缺失文件、关闭标签或跨窗口移动时，清理对应树叶并折叠空分栏；独立窗口启动失败还原转移前的布局。

共享工具通过当前编辑器 getter 路由，正文的捕获阶段指针／焦点／拖放事件先切换当前文稿。仅当前视图使用旧的 editor DOM ID，各视图使用共同 class；冻结操作作用于整个编辑工作区。查找面板切栏后重新查询且不挪动正文选区，图片与图表按钮监听稳定容器，媒体回调按视图绑定；公式与 Mermaid SVG 使用各编辑器唯一前缀，避免同屏引用冲突。会话提交前同步所有已加载编辑器，窗口所有权仍由原有主进程接口维护，不新增文件访问权限。

`src/editor-block-handle.ts` 通过 Milkdown 服务工厂管理六点手柄与块菜单。悬停按 requestAnimationFrame 合并，段间空白按最近块判定，控件对齐第一行；滚动和 ResizeObserver 触发重算。菜单固定捕获当前文档、节点与位置，`editor-block-menu.ts` 提供搜索、子菜单、键盘导航和视口约束。高亮通过 ProseMirror Decoration 管理，不改变正文 DOM 的持久属性；切换文档、模式或修改模型会关闭旧菜单。原有“＋”及斜杠插入菜单继续沿用 Crepe。

`src/editor-block-model.ts` 统一处理转换、文字样式、复制、删除和同层移动，操作前核对文档身份与 schema。单个列表项转换会拆分其所在列表，保留前后兄弟项、后段有序编号及嵌套内容；代码转换不吞掉行内公式或图片。`editor-block-drag.ts` 在原生 dragstart 后才设置块选区，拖放使用完整节点和合法块边界，不向段落中间插入开放切片。列表项移出列表时保留列表包装，单项列表移动后清理空容器。插入线、紧凑预览及连续边缘滚动由独立帧循环更新，Alt／Option 可复制；取消、失焦、模型变化和销毁均清理拖动状态，拒绝本次块手势落入其他分栏。每次修改隔离撤销历史，悬停、菜单与复制不重写 Markdown。

`src/editor-lists.css` 让列表标记和正文共享首行基线，替代 Crepe 的固定 32 px 标记盒。编号使用自身文字基线；复选框与圆点通过不可见 CSS 生成文字取得相同字体的自然行盒，再将 SVG 居中。生成内容位于不可编辑标记区，不进入 ProseMirror 模型或 Markdown；多行、嵌套、字号及段落行高变化由浏览器布局处理。

选中文字不创建 Crepe 的浮动格式工具栏，格式命令由应用顶部工具栏和快捷键提供。共享外观中的文首 H1 规则只计算正文节点，忽略 ProseMirror widget 与虚拟光标：虚拟光标在折叠选区时插入文首，展开选区时移除，不能让标题的间距跟随变化。打字机居中在两个编辑区的主指针按下期间及非空选区中暂停，避免在鼠标拖动前的折叠光标阶段就改变目标位置；指针结束、取消或窗口失焦后恢复状态，监听随编辑器销毁移除。

分割线使用 `src/appearance.ts` 的共用单条边框，显式清除 Crepe 的背景线、固定高度与内边距，保证编辑和导出采用同一排版。`src/writing.css` 在节点选中时改变边框颜色，关闭默认选中背景层。

`electron/main.cjs` 负责应用启动、单实例路由及共享服务；`editor-window.cjs` 为每个原生窗口创建独立的编辑上下文、菜单、文件授权、工作区与附件／上传事务。`window-manager.cjs` 按发送方 WebContents 路由 IPC，协调窗口创建、文稿归属、移动、并排与退出；不接受 renderer 自报窗口 ID。`file-store.cjs` 管文件、设置、恢复和图片。渲染器不启用 Node，使用 context isolation 与 sandbox，只通过 preload 提供的窄接口调用主进程。文件访问限于用户已打开／选中的文稿和工作区。本地图片读成 data URL，页面脚本不能直接任意读取磁盘。

`src/about-dialog.ts` 提供两端共用的“关于 Meki”窗口；版本读取启动桥接已有的 `boot.version`，因此显示启动器实际选中的更新版本，开发者取自 `package.json`。菜单和侧栏图标共用 `about` 命令；macOS 关闭全部编辑窗口后从应用菜单打开关于，会先恢复编辑窗口。开源组件声明按需加载本地打包的纯文本并以 `textContent` 显示；打包准备在构建之前生成声明，避免界面与交付文本不一致。项目链接复用已有受限外链接口，打开关于和更新窗口均不自动请求网络。

`tests/about-smoke.mjs` 在隔离配置和合成文稿中检查原生菜单、重复打开、版本／署名、离线声明、外链分派、未保存文字保留、更新入口、窄窗口、深色主题和 Escape 焦点恢复；Mac 分支覆盖关闭全部窗口后重新打开关于。`updates-smoke.mjs` 通过实际加载签名更新负载检查关于中的版本跟随更新。Windows 本机通过这两项和多窗口回归；Mac 专用路径仍需在 Mac 上执行桌面测试。

文件替换期间锁住编辑区域，防止等待打开／确认对话框时输入的新内容被覆盖。保存允许继续输入，成功后只把那次保存的快照标为已保存，其间的新输入仍保持未保存状态。

`electron/workspace-store.cjs` 管理选中目录下的文件树、搜索、创建、复制和移动。工作区在选择时解析真实路径，后续每次操作检查边界与各级目录，拒绝符号链接／junction、工作区根目录变更和受保护路径；目录操作先检查整个子树。新文件以排他方式创建，复制保留原始字节，删除只通过主进程的确认框和 `shell.trashItem`。操作成功后即使可选的历史记录写入失败，也会向渲染器返回实际新路径，避免继续把修改写到旧位置。

文件改名／移动通过 `link` 排他创建目标，核对源 inode 后才移除旧名字；不支持硬链接或跨卷时失败，不回退到会覆盖目标的 `rename`。Windows 目录 `rename` 会拒绝已有目标；POSIX 先用 `mkdir` 排他保留目标名称，确认仍是本次创建的空目录后再替换。新加入的内容会使替换失败，失败只清理本次保留且仍为空的目录。Node 没有可移植的 `renameat2(RENAME_NOREPLACE)`，外部进程刻意删除并替换保留目录仍存在最终系统调用间的极小窗口；应用不宣称抵御操纵本机文件系统的恶意进程。测试注入目标在检查后出现的竞态，验证文件及目录内容不会被覆盖。

`src/workspace-ui.ts` 负责折叠目录树、排序、路径筛选、文件操作对话框、快速打开和内容搜索。文件打开与搜索结果进入标签管理，同一路径只保留一份打开状态。重命名、移动及父目录更改迁移全部相关文稿路径、会话与历史，保留内存内容、修改状态与 SHA-256 版本；删除后保留未保存的内存副本。不会批量改写文稿链接，移动对话框明确提示资源和相对路径的影响。树、搜索与目录复制都有数量和大小上限。

`src/workspace-navigation.ts` 根据折叠、排序与筛选生成可见行及 `aria-level`、`aria-posinset`、`aria-setsize`；文件树使用单一 roving tab stop，焦点与已打开文稿分别表示。方向键行为参考 [WAI-ARIA Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)。刷新保留同一路径的焦点，路径消失时依次找可见父项和相邻行；空树返回新建按钮。文件操作先迁移导航路径，再通知标签刷新，避免更名期间旧路径失效使焦点提前跳走。树的右键操作也可用 Shift F10、方向键和 Esc 完成。

最近文件夹存于 `state.json` 的独立 `recentFolders` 字段，不替代 `recentFiles`。FileStore 在同一 metadata 锁内更新、排序和原子持久化，最多 20 条、10 个固定项、128 KiB 元数据；旧设置缺少此字段时默认空列表。记录读取与固定操作不解析文件系统、不增加文稿授权；只有原生目录选择或显式 `openRecentFolder` 成功时才读取工作区并授权其文稿。最近位置还要求 realpath 与已记录路径相同，防止目录被链接到别处后沿用旧授权；启动恢复上次工作区同样检查。列表不主动清除失效位置，实际打开会给出错误，用户可自行移除或重新选择。清除未固定记录保持当前工作区、标签及最近文稿。

导航的单元测试覆盖记录迁移、去重、容量、固定上限、并发持久化、键盘状态与焦点回退；独立 Electron 测试使用隔离目录验证实际按键、F2 更名、刷新与折叠、筛选、固定后重启、失效目录、链接替换、授权隔离以及不丢失未保存标签。未进行真实屏幕阅读器的人工验收。

`electron/window-sessions.cjs` 将所有窗口的会话、位置和工作区原子保存到 `windows-v1.json`，最多 8 窗口、128 MiB 正文。每窗仍使用 `lifecycle-store.cjs` 的验证与恢复规则，最多 24 个标签、48 MiB 正文；所有窗口的标签 ID 与文件路径唯一。旧版 `session.json` 在首次启动时迁移，随后保留主窗口的兼容副本；兼容副本写入失败不撤销已经成功提交的新格式。两个格式均在覆盖损坏记录前排他备份并同步，备份失败则保留原数据。旧版单草稿在全会话写入成功后迁移清除。

`electron/closed-documents.mjs` 为每窗保留有界的内存关闭栈（20 份／32 MiB），只保存正文、基线、模式和滚动位置，不保留编辑器撤销树。`DocumentTabs` 在关闭持久化成功后入栈、恢复成功后出栈，取消、窗口关闭及跨窗口移动不入栈。干净文稿重读磁盘；脏文稿经过主进程复验 revision、规范路径和窗口占用后恢复，发生变化时建立未命名副本并暂停自动保存。会话已经提交后的旧草稿清理失败只记警告，避免界面回滚后与主进程归属不一致。

`electron/shortcuts.mjs` 是主进程和 renderer 共用的纯策略，定义命令、默认键、格式化、保留键与冲突校验。设置经单命令更新接口串行持久化，随后广播到其他窗口。原生菜单显示相同映射；匹配的应用快捷键交给 renderer 单次派发，旧默认键不会落入 CodeMirror 的备用查找／粘贴处理。录制和模态对话框期间屏蔽原生菜单快捷键，输入法组合与 AltGraph 不作应用命令；普通文字编辑键保留原行为。

会话持久化内容、路径、脏状态、编辑模式和自动保存暂停原因，不序列化编辑器撤销树。正常退出前标记 `cleanExit`；启动时已保存标签重新读取磁盘，意外退出的脏标签保留恢复文本与原 revision，即使关闭“打开上次会话”也会恢复。独立关闭只移除对应窗口；退出应用先逐窗确认，把同意保存／放弃后的会话暂存在主进程，所有窗口同意后再统一提交并关闭。任一窗口取消或失败，不提前删除其他窗口待放弃的恢复内容。

移动文稿先原子转移会话归属，再等待新窗口初始化完成，最后移除源标签；新窗口失败则原子回滚。标签 ID 保持不变，未命名文稿的快照继续归属于它；跨窗口移动不搬运撤销树。同一文件再次打开会激活拥有它的窗口，保存过程也临时占用目标路径，防止两个窗口同时另存到相同位置。影响其他窗口已打开文稿的工作区移动、改名和删除被拒绝。窗口各自隔离文件操作与上传取消，设置、历史和快照使用共享实例及串行锁；设置变更广播到各窗口，原生菜单随焦点更新。

自动保存默认关闭，顶部与原生文件菜单均有开关。`DocumentTabs` 为各标签记录最后编辑时间，停止输入 2–600 秒（默认 30 秒）后提交；`autoSaveOnBlur` 默认开启，窗口失焦时跳过等待时间。输入法组合期间与模态对话框打开期间不触发后台任务。主进程再次验证开关、标签授权和暂停状态；后台标签也经过 SHA-256 检查。自动保存不进入原生冲突选择循环，冲突或错误使该标签暂停并显示原因，手动保存或重新载入后才能继续。历史／快照恢复、附件整理和崩溃恢复默认暂停。保存成功只更新提交时文本的基线，晚到输入保持脏状态；手动另存为还根据当前已打开路径拒绝覆盖其他标签。会话恢复数据写入失败不会禁止用户手动保存单份合规文稿。

`electron/snapshot-store.cjs` 将编辑区文本独立保存到 `snapshots-v1/`，不变更旧会话和文件历史格式。保存文件以规范路径为身份，未命名文稿以会话标签 ID 为身份；首次保存成功后迁移其快照，另存已有文件保留原文件的快照系列。工作区移动同步路径，删除保留旧路径记录，可在全部文稿库中找回。快照 IPC 创建时必须匹配已持久化会话的标签与授权路径；读取仅返回受控存储的文本，不用索引路径读取外部文件。名称只作为文本显示，内容预览是只读 textarea。

快照使用独立串行锁、UUID 文件、SHA-256 校验与原子索引替换。先提交新索引再移除被淘汰的文件，索引提交失败则保留旧数据并清理本次新文件。索引损坏时保留原数据并禁止覆盖；目录、索引和内容文件拒绝链接，启动仅清理不在有效索引中的 UUID 内容文件。每篇上限 20 份／32 MiB，总计 128 篇／128 MiB；手动快照不自动淘汰，自动及恢复前快照按时间清理，无法满足容量则拒绝新快照。自动快照默认每 60 秒在内容变化时创建（可设 10–600 秒），独立于磁盘写回并对未变化文本去重。`src/snapshots.ts` 提供当前／全部文稿列表、命名、预览、恢复、新文稿副本及原生确认删除。恢复时先持久保存当前缓冲区，备份成功后才替换并暂停自动保存；恢复失败不丢当前输入。

历史存储在 `versions/` 的受控哈希目录与索引中。FileStore 在最终原子替换前，将原文件的精确字节交给 LifecycleStore；历史写入失败会中止覆盖，写入历史后再次校验磁盘 revision，防止历史 I/O 期间的新外部修改被覆盖。无变化的保存不产生历史，相邻相同 revision 去重。历史最多 20 版／32 MiB 每文稿、128 份／128 MiB 全局，索引提交后清理淘汰内容，启动时清理中断产生的未引用文件；拒绝链接目录并校验历史内容哈希。历史读取只返回 UTF-8 文本，恢复在渲染器中产生未保存内容，不调用磁盘保存。更名合并并迁移历史，回收站操作保留原路径历史。

生命周期的 Node 测试覆盖会话验证、恢复开关、并发写入、BOM/EOL 历史、覆盖前错误与竞态、容量淘汰、路径迁移和受控存储。独立 Electron 合成文稿测试覆盖多标签源码／视觉撤销、同文件去重、异步保存输入、关闭确认、真实间隔自动保存、后台冲突暂停、历史内存恢复、多标签目录操作和正常／异常重启。

`src/attachment-markdown.ts` 使用现有 remark 解析器确认图片 AST，再用 micromark 原始 token 定位地址范围，只替换当前内存快照中的图片地址；不重序列化整篇 Markdown。引用式图片只转换该图片为行内语法，保留共享定义和普通链接；安全的单个 `<img>` 通过 `image-syntax.ts` 精确替换 src，尺寸、说明、标题与引号格式保留。代码、YAML、公式和其他 HTML 不进入替换集合。`attachment-organizer.ts` 预览期间冻结编辑区，复制前后检查标签身份、路径、revision 和文本；编辑器以独立撤销组应用替换，并保存 `attachments` 暂停原因，待手动保存。

`electron/attachment-store.cjs` 是只用 Node 内置模块的窄文件接口。预览验证已授权的文稿和已打开工作区范围（没有工作区时限于文稿目录），沿每级路径拒绝符号链接／junction、越界及受保护目录，并核对图片格式。一次最多 32 个不同来源、80 MiB，每图 20 MiB；base64 data URL 按内容去重，本地图片按真实路径去重，目标目录内的图片复用。普通整理中的远程地址只计数、不访问；单图显式下载另走受限下载接口。五分钟预览令牌绑定磁盘 SHA-256、图片哈希与目标，确认时重新检查；正文允许包含未保存编辑，不要求它等于磁盘文本。

复制通过唯一名称与 `wx` 排他创建，随后同步文件。渲染器应用引用成功后确认保留副本；失败只回滚本次创建且身份和内容仍匹配的文件，已经被外部修改的副本保留并提示。原图片及 Markdown 磁盘正文不参与删除或重写。崩溃只撤销令牌，不推断副本可删除，以免损坏已写入恢复快照的引用。Node 的路径 API 无法彻底隔离恶意外部进程在检查与系统调用间替换目录的竞态，应用不作此保证。

附件单元测试覆盖 AST 原文范围、共享引用、尺寸标签、复制去重、批次大小、格式、外部修改、链接越界、部分失败回滚和崩溃恢复。独立 Electron 测试验证实际预览／取消、原生菜单、内存脏状态、暂停自动保存、源码与视觉撤销、标签切换、恢复副本、BOM/CRLF 保存及 IPC 验证；所有测试只使用隔离的合成图片和文稿。

外部变化检查在窗口前台按约 2.5 秒轮询并响应窗口焦点，树变化仅更新导航；当前文稿的 SHA-256 变化或丢失只触发重载提示，不自动覆盖编辑区。相对 Markdown 链接在主进程解码、解析并验证真实路径，再授权打开；允许工作区内的 `../`，没有工作区时以当前文稿目录为边界。标题锚点使用已有的 Markdown 标题 ID，搜索结果定位源码行列。

`src/media-controller.ts` 统一接收原生多图选择、剪贴板图片与文件拖放，记录文稿代次、编辑模型和插入选区。本地附件模式下，未命名文稿先走正常保存流程；整个异步过程冻结编辑与切换，并在写入前后校验身份。主进程验证批次大小、扩展名和图像字节，按已保存的图片目录设置，以独占文件名写入附件；批次失败只回收新写入的附件。源码图片插入不会落到 YAML 前缀内。原有 Crepe 上传控件也接入同一保存保护。

`src/image-hosting.ts` 提供 PicGo 设置、手动上传预览与进度／取消窗口。`electron/image-hosting.cjs` 固定连接 `127.0.0.1` 上的配置端口，`POST /heartbeat` 只检测连接，`POST /upload` 只发送非空的已验证临时文件路径数组。拒绝重定向、超大响应、不完整结果及非 HTTP(S) 地址，不读取 PicGo 配置或云端凭据。

手动上传复用附件解析中的 Markdown token 范围以及主进程的受限图片读取：预览记录磁盘版本、原图摘要与工作区，上传前后复验，向 PicGo 提供独立临时副本而非原文件。成功后按原始 token 范围更新源地址，保留说明、标题、尺寸和非图片内容，形成单次可撤销编辑并暂停自动保存。临时目录、文件身份及内容在发送前复核；只清理本次仍归属该请求的临时文件。

自动上传默认关闭，主进程也检查该设置；新插入的图片成功时直接使用图床地址，可用于未命名文稿。失败／取消时回到本地附件保存流程，不自动重试远端上传。文稿 YAML 不具备开启上传的权限，已有网络图片不会被下载后再上传。PicGo 接口与功能边界见 [image-hosting.md](image-hosting.md)。

`electron/image-destination.cjs` 为插入和附件整理共用相对目录解析，支持文稿／工作区基准及 `${filename}`，逐层复验普通目录并记录本次创建的目录身份。`src/image-actions.ts` 在图片上提供单张上传、命名副本和显式下载入口；引用替换复用 Markdown token 范围与单次编辑事务。下载由 `image-download.cjs` 限制 HTTP(S)、大小、时间和重定向，对每一跳解析并固定公开 IP，不携带浏览器 cookie 或凭据。完成后暂停自动保存，保留原图和已被恢复内容引用的副本；取消仅回收仍归属本次操作的文件。

`src/image-syntax.ts` 严格识别独立的单个 `<img>`，只允许 src、alt、title、width、height，验证地址与整数尺寸；未知属性、事件、样式及混合 HTML 保留可见源码。AST 的 `moyeImage` 与编辑器图片节点共用该规则。`src/editor-images.ts` 保留原图片控件，将拖动结果作为独立历史事务写入像素尺寸属性，标题输入同步提交；拖动期间文档改变会取消操作。未缩放图片继续序列化为标准 Markdown，带尺寸图片使用受限标签，图片描述和标题独立保留。剪贴板 DOM、HTML 和打印均保留 width/height 属性；去除 CSS 的转换输入也不会丢掉尺寸。没有修改的文稿仍直接保存原始字节。

`src/editor-actions.ts` 将格式菜单操作转换成 ProseMirror 历史事务或 CodeMirror 变更；链接、脚注和表格对话框在确认时重新验证文档快照，源码块格式以整行为单位。图片专用的 `captureImages` 将源码无选区插入点移到逻辑行末，避免拖放坐标或光标切断既有图片 URL；明确选择的替换范围保持不变。表格保留 GFM 所需的专用表头节点，删除表头会将下一行提升为表头，增行沿用 Milkdown 命令。`editor-table.ts` 保留 Crepe 表格控件，让单元格普通点击由 ProseMirror 同步处理，避免其延迟选区事务与快速输入冲突。代码复制只给受信的主页面开放浏览器剪贴板写入权限，浏览器剪贴板读取和其他权限仍拒绝。

`src/editor-code.ts` 使用 CodeMirror Compartment 配置换行、缩进单位、Tab 列数和 Enter 命令；跟踪代码块视图的挂载与销毁，恢复懒加载视图时应用最新设置。语言描述来自已有本地 `@codemirror/language-data`，按需加载打包后的语法模块。默认语言只应用于显式新建块，文稿加载、模式转换和粘贴事务受保护；语言记忆在选区进入或编辑代码块时更新。`code-options-dialog.ts` 提供独立设置界面，`code-options.ts` 共用屏幕／HTML 代码排版与打印强制换行规则，不改写已有缩进。

`src/editor-clipboard.ts` 为四个显式剪贴板命令构建独立模型事务。`electron/clipboard-text.cjs` 只通过受信主页面 IPC 读写限长的 text/plain，不接受格式名、HTML 或文件路径。纯文本粘贴直接建立段落／代码文本，Markdown 粘贴使用当前编辑器解析器；因此都绕过 Milkdown 的 HTML 和 `vscode-editor-data` 分支。读取前捕获模型、原选区和文稿代次，读取完成后验证文稿与模式身份；即使两个空文稿共用 CodeMirror 的空文本对象，切换文稿仍使旧请求失效。新输入也会取消旧请求，成功粘贴构成独立撤销事件。源码模式读写字面 Markdown；查找等输入框有焦点时操作该输入框，并校验等待期间值未改变。普通粘贴和图片处理保留原路径，系统菜单与 Ctrl／Cmd 快捷键共享命令。

`src/outline.ts` 使用共用 Markdown AST 建立 H1–H6 层级和源码位置，不把代码围栏、HTML 或 YAML 中的伪标题列入大纲。`outline-panel.ts` 保留折叠状态，监听当前编辑区滚动并标记当前章节，支持隐藏子标题的父项跟随。`tests/media.test.cjs` 和 `tests/media-smoke.mjs` 覆盖附件完整性与失败回收、真实剪贴板、多图拖放、保存取消、异步切换保护、图片显示、大纲层级与跳转，以及两个模式的格式菜单、表格和代码操作。

`src/heading-numbering.ts` 是不依赖 DOM 的编号规则，按真实标题祖先生成序号，跳级不创建空章节。编辑器的 `heading-numbering` 插件状态只通过非历史事务保存开关，以节点装饰附加 `data-heading-number`，加载新文稿后重新应用偏好；标题模型与锚点生成不含编号。目录、大纲和 `renderMarkdown` 共用同一规则；正文前缀由共享外观 CSS 显示，因此 HTML 与 PDF 排版一致。空标题只在导航标签中补“未命名标题”，不会改原文。专项测试覆盖跳级、重复与空标题、文稿切换重置、设置持久化、导出，以及未编辑时的 BOM/CRLF 字节保留。

`src/search.ts` 定义文字匹配与正则替换规则，`search-client.ts` 将匹配放入可终止的本地 Worker，限制复杂正则耗时和匹配数量。`editor-search.ts` 把 ProseMirror 的连续文字映射到块内位置；公式与原始 HTML 属性作为独立文本域，源码模式直接映射 CodeMirror 文档。查找装饰不会修改文档；替换检查文档快照仍有效后，在当前编辑器中提交单次历史事务，支持单步撤销。切换文稿、模式或查询会废弃旧结果。

打开查找前，`writing-tools.ts` 从当前编辑模型提取有界单行选区，正则模式下先转义字面选词；面板内重按快捷键或没有选区时保留查询。Ctrl／Cmd F 在捕获阶段处理，避免源码编辑器打开另一套查找界面。匹配导航按模型／高亮位置滚动所属 `.document-scroll`，不依赖浏览器选区仍在正文中，也不夺走查找框焦点；源码与代码块使用 CodeMirror 滚动效果。代码块视图挂载时补齐高亮，并完成离屏代码的待执行定位；关闭查找清除装饰，延迟回调核对当前文稿和匹配项，避免旧结果移动其他分栏。

`src/editor-writing.ts` 根据当前选区统计字数、标记活动段落，并在输入／光标改变后按可见编辑区居中滚动。写作辅助默认关闭，设置经主进程验证保存。段落淡化与打字机留白仅作用于编辑界面，打印禁用淡化过渡和留白，HTML 导出不附带这些装饰。拼写检查在 Electron Session 和两个编辑区同步启停，右键建议使用 Electron 原生接口，词典由平台提供。`tests/search.test.cjs` 与 `tests/writing-smoke.mjs` 覆盖匹配、跨模式替换与撤销、超时、选择统计、滚动位置、打印隔离及设置持久化；拼写建议的实际质量和不同语言词典仍需对应系统验证。

`src/typing-rules.ts` 是输入改写的纯规则，`editor-typing.ts` 将结果作为独立历史事务应用到 ProseMirror，并排除代码、数学、跨段、内联原子和输入法组合。自动括号仅跟踪本插件生成的关闭符号，删除或替换后清除位置记录。源码继续使用 CodeMirror 原有 `closeBrackets`，通过语言配置切换开关，恢复旧标签状态时重新应用当前偏好，不安装第二份输入处理器。新增偏好默认保留原行为；智能标点及 Markdown 选区格式化只作用于视觉正文。

`src/markdown-extensions.ts` 以 micromark token 和 remark AST 实现目录、提示块、高亮、上下标和常用 emoji。编辑器的 schema／序列化适配在 `src/editor-extensions.ts`，导出路径在 `src/markdown-render.ts`，两者共用语义规则；脚注使用 remark-gfm。除受限的单图片标签外，原始 HTML 作为可见源码，不在编辑或导出时执行。YAML 仍保存在模型外。

`src/math-engine.ts` 接受整份文稿按顺序排列的公式，使用新建的 MathJax TeX/MathDocument 统一解析、二次处理前向引用，再输出 SVG 和标准 MathML。MathML 来自同一编译树，去除页面 ID 和跳转属性，因此复制的宏与引用和正文一致；公式错误不提供 MathML。每次文稿重算隔离宏、标签和计数器。`src/editor-math.ts` 将结果应用到节点视图；保存／打印前可同步刷新。`src/math-copy.ts` 提供显式右键与对话框复制入口，只写剪贴板文本，不改文稿。字体范围和 mhchem 的特殊字形全部随包附带，不安装动态加载、HTML、链接或图片扩展。颜色参数额外拒绝 SVG paint URL。公式对话框使用独立渲染上下文，不影响正文编号。

`src/diagram-engine.ts` 为编辑和导出提供同一异步 Mermaid 12 渲染器；标准图表模块由 Vite 编译成应用内本地分块。渲染队列将配置初始化和图形布局串行处理，避免同时切换主题时互相污染；缓存按源码、主题和节点身份区分。`src/diagram-policy.ts` 在测量 DOM 建立前拒绝文稿配置、交互链接、HTML、图片和 CSS 外部资源。Mermaid 固定使用 strict 安全模式、SVG 文本标签和应用主题，不调用其绑定回调、不注册远程图标包。

生成的图表再经 DOMPurify 清理，CSS 属性受限且选择器约束在该 SVG 内；重命名全部内部 ID 并同步引用，防止多幅图表的箭头、渐变或样式冲突。仅保留 SVG 内部的资源引用；需要 HTML 布局的标签返回明确错误和原始源码。`src/editor-diagrams.ts` 遍历 ProseMirror 文档，不依赖可见节点数量，给 CodeMirror 的离屏占位节点补齐 SVG。异步结果带文档代次检查，避免旧文稿或旧主题覆盖新内容；插件重建会重置状态。

`src/export.ts` 先用统一的 Markdown 规则生成并经 DOMPurify 清理 HTML，再插入受控公式和图表引擎的 SVG；本地图片经主进程确认范围后嵌入。`src/code-highlight.ts` 共用编辑器的本地语言解析器和高亮类别，为导出代码生成纯文本／span 节点；未识别或加载失败的语言保留完整原文，不运行代码。

`src/appearance.ts` 同时为编辑器和导出生成正文 CSS，统一标题字体、字距、链接、引用、表格、行内公式及代码排版。PDF 保留当前主题和高亮配色，使用精确打印颜色，不再强制替换为白底；页面背景延伸到页边距，页眉和页码采用经校验的正文颜色。分页规则防止标题悬空、尽量保留整块引用／表格行，并让长代码换行；编辑器工具和代码行号不导出。导入的样式经属性白名单、资源过滤及选择器限制后只作用于正文，用户明确写出的打印规则继续生效。

导出先同步读取一份 Markdown 与外观快照，后续输入不影响正在生成的文件，也不会被导出结果覆盖。`src/export-dialog.ts` 提供格式、PDF 纸张／方向／边距／页眉页码及 PNG 宽度／倍率选项。`electron/export-policy.cjs` 在 IPC 边界复验类型与限制；不接受文稿指定输出路径或任意打印参数。

`electron/export-presets.cjs` 在共享用户目录保存命名预设和 Word 样式模板副本，每次操作在跨窗口共享锁内重新读取并原子提交索引。模板只通过原生文件选择授权，以 UUID 引用；`docx-template.cjs` 检查 ZIP 边界、校验和及 OOXML 资源，拒绝宏、嵌入对象、外部资源和路径越界，允许被动网页超链接。导出前复验副本摘要，再交给 Pandoc 临时目录中的固定 `--reference-doc` 参数。损坏索引不会阻止应用启动或无模板导出。

HTML／PDF／PNG 的主题和字号覆盖只作用于导出设置快照；PDF 一级标题分页使用打印 CSS，从第二个根级 H1 开始。模板样式影响 DOCX，正文与公式仍来自当前文稿；预设不携带输出路径、过滤器或任意命令。

`electron/export-service.cjs` 将完整 HTML（包含离屏公式和图表）写入独立临时目录，并用无 preload、隔离 session 的隐藏离屏 BrowserWindow 渲染。第一条 CSP 禁止脚本，session 同时阻止网络、外部文件、导航和权限请求；只允许当前快照主文件和 data URL。等待字体与图片解码后，PDF 用 `printToPDF`，PNG 用 Chromium 截图。错误图片直接失败；PNG 的物理尺寸和像素数量均有限制。渲染最多 45 秒；成功、失败或超时均关闭窗口并清理临时目录。

`src/export-assets.ts` 为无样式 HTML、DOCX、EPUB 把受控 SVG 转成 3 倍分辨率 PNG，在移除正文 CSS 前把标题编号转为正文文字，并保留逻辑显示尺寸；转换使用纸白主题。Word 的中间 HTML 额外携带受限 MathML 与 PNG 回退，普通 HTML 不包含此交换数据。样式 HTML、PDF 和文稿 PNG 仍从完整 SVG 生成。图表另存 SVG／PNG 与复制图片使用同一图形快照；SVG 主进程复验活动内容及外部资源，PNG 在解码前检查文件头及尺寸。剪贴板通过 Electron 45 的异步 `ClipboardItem` 写入限定的 `image/png`。

`electron/pandoc-service.cjs` 仅启动用户选择或 PATH 中的 Pandoc 3.12.1 及更新版本，`execFile` 使用固定参数数组，不使用 shell。每次转换使用独立工作目录、`--sandbox` 和空的 data-dir，45 秒执行上限与 512 MiB Haskell 堆限制。输出先转 Pandoc JSON AST，清空文稿元数据，禁止 raw HTML 执行，仅允许已验证的内嵌位图；不接受任意 filters、模板或命令行配置。

Word 公式由 `electron/word-math.cjs` 再次检查 MathML 标签、属性、长度及私用字形，最多批量转换 256 种不同公式，并用实际 DOCX writer 预检。支持的公式替换成原生 Math AST，最终写为 OMML；特殊节点、颜色、编号布局及转换告警保留原 PNG。导出返回可编辑和回退数量，在 UI 明确提示。EPUB 公式与所有 Mermaid 图表继续用图片，保留视觉内容。

DOCX／HTML 导入复制输入到临时目录，转换为 JSON 后再写 Markdown。只读取 DOCX 提取目录中的真实路径，图片以 data URL 写入；不读取 HTML 旁边的文件或远程资源。不支持的图片保留说明，原生公式转为 TeX。Windows 临时目录先规范为真实路径，避免 8.3 别名造成错误的范围判定。导入结果无路径且标为未保存；原文件加入当前会话的导出保护集合。转换前后临时目录都会清理，导出最终文件经原子替换写入。

## 应用内更新

`electron/bootstrap.cjs` 是安装包的固定入口，先取得单实例锁，再从用户数据目录 `updates-v1/` 选择已签名、平台匹配且版本更高的 ASAR；没有有效更新时运行安装包内代码。签名公钥随安装包固化，Ed25519 清单同时绑定版本、Electron 版本、启动器 API、压缩包及解压后 ASAR 的大小与 SHA-256。缓存读取使用 Electron 的 `original-fs`，避免将 ASAR 当作虚拟目录。代码包保持只读，不改写 Windows 安装目录或 Mac 签名应用包。

`UpdateService` 经受限 preload IPC 提供检查、认证、下载、取消及应用操作。只有用户操作才发起网络请求，优先匿名访问固定的 Meki 公开仓库。仅当公开仓库没有适用平台的发布、且用户连接了旧仓库登录时，才读取原私有仓库；网络错误、限流、坏签名或损坏文件不能触发降级兜底。访问令牌仅保留在会话中，或通过 Electron safeStorage 加密；公开更新不读取 CLI 或解密凭据，凭据也不随重定向发送。renderer 只接收实际仓库名，不接收令牌，版本说明作为纯文本显示。

最新版缺少当前平台资产时，更新器从最多 20 条发布记录中选择版本最高且具有清单、代码包和安装器的正式发布，再进行原有签名与摘要检查。这样 Windows 单平台发布不会让 Mac 选择一个无法安装的版本；找不到完整发布时明确提示。

下载采用独立临时文件，限制压缩与解压大小；签名、SHA-256 与运行环境检查通过后才进入就绪状态，不自动启用。应用更新要求先关闭其他编辑窗口，再沿用文稿关闭流程 flush、保存／放弃／取消，并暂停输入；完成后主进程复验缓存，提交最终会话，原子写入新版本及回退指针，再重启。应用失败时重新持久化仍在内存的文稿。启动器先标记启动尝试，renderer 完成命令初始化后确认健康；未确认的下次启动回退到上一有效代码包或安装版。健康启动仅清理过时的已命名更新文件，保留当前和回退版本。

运行时或启动器不兼容时，软件内下载同一签名清单绑定的完整安装器，复验后交给系统打开。Windows 继续使用 NSIS，Mac 继续使用拖放安装。测试只记录安装器启动请求，不在开发机执行安装器。首次安装入口、密钥管理和发布资产见 [updates.md](updates.md)。

## 中英文界面

`electron/i18n.mjs` 由主进程和渲染器共用，以中文源文案为键，`electron/locales/en.json` 提供英文词库。`t` 仅替换数字占位符，动态参数不再递归翻译；`ht` 转义 HTML 模板中的固定文案，参数沿用调用处已有的转义或受控图标，不扫描渲染后的文稿 DOM。新建示例可本地化，用户文稿、路径、预设名和外部版本说明不翻译。

`Settings.locale` 严格接受 `zh-CN`／`en`，缺失或无效配置回退中文。主进程启动时确定有效语言，`boot.locale` 与可能尚待重启的 `settings.locale` 分开；渲染器由 `src/boot.ts` 先设置语言，再动态加载含静态菜单标签的组件。设置同步到其他窗口，但当前进程的界面语言保持一致，退出重启后应用。快捷键名称和原生文件筛选器按有效语言读取；安装启动器与更新负载的词库实例共用进程内语言，查找 worker 显式接收当前语言。

`tests/i18n.test.cjs` 检查词条覆盖、占位符一致性、HTML 转义、动态数据不被翻译、设置验证与持久化。`tests/i18n-smoke.mjs` 通过真实 Electron 窗口检查两种语言、跨窗口偏好、重启恢复、原生菜单、主要对话框、worker 错误、自定义名称、导出与窄窗口布局。测试使用隔离数据和合成文稿，验证原文件 BOM／CRLF 字节不变；macOS 共用实现，仍需 Mac 实机验收。

## 跨平台打包

没有平台专用业务模块或原生 Node 扩展。Windows 使用原生窗口边框，macOS 使用 hiddenInset 窗口与应用菜单；快捷键使用 CmdOrCtrl。0.11 起交付 Windows x64 NSIS EXE 和 macOS universal DMG；同一份 DMG 在 arm64 与 x64 上验收。

`stage-application.mjs` 只装入 dist、electron、原创图标、README 和许可，不含源码依赖树。`installers.mjs` 使用锁定的 electron-builder，记录提交、安装器和 ASAR 摘要。Windows 使用辅助安装向导，可选用户范围与目录；自有 ProgID 只加入 OpenWith，不更改扩展名默认值或 UserChoice。卸载清理本程序注册，保留应用数据。Mac 在真实 Mac 构建机合并两种架构、ad-hoc 签名并生成带 Applications 链接的 DMG；未做 Developer ID 公证。

CI 将构建产物传给独立安装验证任务，三个平台直接运行安装后程序的完整桌面套件。Windows 还验证快捷方式、卸载入口和默认文件关联不变；Mac 验证 DMG、签名及通用二进制。重新安装与卸载均检查隔离文稿和设置保留。发布直接复制通过检查的 CI 安装包，不用另一次本机构建替换。

普通 push／PR 触发 Source CI，只执行构建与单元检查。涉及交互的修改仍按开发约定运行本地桌面回归。包含两个安装包构建与三个安装验收任务的 Desktop CI 仅支持手动触发；只有用户明确要求发布时才运行，不随日常提交、push 或版本号以外的改动自动启动。

旧的 Packager/ZIP 脚本保留为便携开发路径。Windows 交叉打 Mac 便携包时修正 Packager 20.3 的 ASAR plist 资源键，ZIP 保留 Mach-O 执行权限和框架的相对符号链接；正式 DMG 使用原生 Mac 路径。
