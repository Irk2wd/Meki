# mekiR 应用内更新

[使用说明](README.md)

## 检查与安装

从帮助菜单或侧栏打开「检查更新」。默认在启动后及每 6 小时检查一次，只在发现适用于当前平台的 mekiR 正式更新时提醒。下载和安装由你确认，自动提醒可以在更新窗口关闭。

mekiR 在联合发布 `v<版本>` 和研究版发布 `mekir-v<版本>` 中检查自己的签名清单、代码包和安装器。应用按 mekiR 版本号选择最新版本，并校验清单内的应用 ID。更新缓存和提醒偏好保存在 mekiR 的应用数据目录中。

应用优先从国内 HTTPS 镜像检查和下载。镜像暂不可用、清单过旧或文件校验失败时，应用会自动回退到 GitHub。若已经选定要下载的版本，回退时会继续下载该版本。

通常只需下载代码包并重启。运行环境或原生图标变更时，应用会下载完整安装包。Windows 运行 EXE，macOS 将 DMG 中的 mekiR 拖入 Applications 并替换已有应用。

## 从 1.1.4 升级

mekiR 1.1.4 需要先用带更新功能的新安装包升级。请从发布页下载以 `mekiR-` 开头、对应系统的安装包。[版本列表](https://github.com/Irk2wd/Meki/releases)

研究项目与附件保存在你选择的项目目录。应用设置、恢复数据和历史记录位于系统应用数据目录中的 `mekiR` 文件夹。

## 构建与发布

日常提交和 PR 在本地验证。需要在 GitHub 检查源码时，可手动运行 `Source CI`。发版时，版本标签触发的 `Desktop CI` 会构建并验证安装包。

研究版通过 `mekir-v<版本>` 标签触发安装包构建。发布流程按两版各自上次正式发布的源码检查待发布改动。仅 mekiR 有改动时，发布 `mekir-v<版本>`。仅 Meki 有改动时，在 `v<版本>` 发布 Meki。两版都有改动时，各分支使用同一个新版本号，一起发布到 `v<版本>`。

联合发布的版本号须高于两版各自已发布的最高版本。先推送准备好的分支提交，再推送同号的 `v<版本>` 和 `mekir-v<版本>` 标签。发布构建使用 `MEKI_UPDATE_SIGN_KEY` 签署 Windows 和 macOS 的研究版更新清单。

正式发布须收到用户明确的发版指令。安装包验证通过后，在 `main` 手动运行 `Publish release` 并填写目标标签。
