# 应用内更新

## 检查与安装

从帮助菜单或侧栏打开“检查更新”，查看版本说明，再选择下载和重启。启动应用不会自动检查或下载。重启前逐份处理未保存文稿；取消保存会取消更新操作，多窗口运行时需要先关闭其他窗口。

更新器匿名访问 `electron/app-identity.cjs` 中的 `REPOSITORY`。公开更新无需 GitHub 登录。只有公开仓库没有当前平台的完整正式更新、且用户已配置兼容登录时，才尝试 `LEGACY_REPOSITORY`；凭据只发给对应的私有 API 请求，不发送至公开仓库或资产重定向地址。

记住的令牌由系统安全存储加密。支持本机 GitHub CLI 和只授予更新仓库 Contents 读取权限的令牌；应用不携带用户凭据。网络错误、限流或签名校验失败不会转向其他仓库。

轻量更新下载压缩的 ASAR 代码包，保留已安装的 Electron 运行时。运行时、启动接口或安装行为发生变化时，更新器改为下载完整 EXE／DMG，由用户运行安装器。macOS 安装后需将应用拖入 Applications。

## 签名与协议

`electron/update-key.cjs` 固定 Ed25519 公钥。签名清单绑定应用标识、平台与架构、版本、Electron 版本、启动器要求，以及 ASAR、压缩包和安装器的大小与 SHA-256。下载、解压和启动均复验；校验失败的文件不会启用。

`update-policy.cjs` 的 `BOOTSTRAP_VERSION` 是固定启动入口的协议版本。修改无法由代码包完成的启动或安装行为时应增加它。公钥、持久化目录和资产前缀是兼容协议的一部分，变更时必须设计已有客户端的信任和数据兼容方案。

客户端只接受更高版本的正式 Release。若最新 Release 没有当前平台的完整资产，最多读取 20 条发布记录，选择版本最高且同时具有签名清单、代码包和安装器的当前平台发布。

## 发布资产

版本在 `package.json`、`package-lock.json` 与发布标签中保持一致。在原生构建环境生成安装器，并从同一最终 ASAR 生成代码包和签名清单。Windows x64 与 macOS 通用版各自提供完整的一组资产：

| 平台 | 主安装器 | 签名清单 | 压缩代码包 |
| --- | --- | --- | --- |
| Windows | `Meki-<版本>-Setup-x64.exe` | `Moye-update-windows.json` | `Moye-<版本>-windows-app.asar.gz` |
| macOS | `Meki-<版本>-macOS-universal.dmg` | `Moye-update-macos.json` | `Moye-<版本>-macos-app.asar.gz` |

每个平台另提供 `Moye` 同名规则的兼容安装器，与对应主安装器逐字节相同；签名清单使用兼容文件名。构建与交付验证同时核对两份文件，不能只上传其中一份。通过轻量代码更新升级后，已安装的宿主和系统快捷方式仍可显示原名称，完整安装 Meki 后才更新系统安装信息。

`Moye` 前缀、`io.moye.editor`、`MOYE_USER_DATA` 和系统应用数据目录中的 `Moye` 属于持久兼容标识，与界面显示名分开维护。

发布时：

1. 提交统一版本的源码与说明，完成构建和相关测试。
2. 手动运行 Desktop CI，在原生系统构建并测试安装器；签名私钥通过 `MOYE_UPDATE_SIGN_KEY` 提供，只用于受控构建，不写入源码或日志。
3. 核对安装器、签名清单、压缩包与解压后 ASAR 的摘要，完成对应平台的安装和更新验证。通用 DMG 需在两种 Mac 架构测试。
4. 使用 `scripts/deliver-installers.py --source-archive <已审阅源码ZIP> ...` 复制已通过验证的原始产物和源码，上传全部资产后再发布正式 Release。

`scripts/verify-update-assets.mjs <平台-build.json>` 仅核对已生成资产，不执行安装或发布。普通 Source CI 不需要发布密钥。安装与卸载测试只在一次性 CI 用户环境运行。

## 缓存与回退

下载位于系统用户数据目录的 `updates-v1/`。`active.json` 指向当前及上一个已校验的代码包。代码包损坏或启动未确认时，下次启动尝试回退，最终可回到完整安装版。成功启动后只保留当前及回退代码包。

更新不搬动文稿、删除原图或改变安装位置。启动确认发生在编辑器命令初始化完成后；它不能发现之后才出现的所有功能回归。数据格式变更应保持向后可读，或另行设计备份与恢复。

单元与桌面测试使用临时密钥、模拟 Release 和隔离数据，覆盖签名、摘要、凭据隔离、平台选择、取消、回退及保存确认。测试模式只记录安装器打开请求，不执行安装器；真实发布的安装生命周期验证以该版本的验证记录为准。
